# Codex стартов промпт

Копирайте/поставете това при стартиране на нов Codex разговор за хранилището:

> Прочетете `AGENTS.md`, `CURRENT_STATE.md`, `docs/methodology.md`, `docs/handoff/CHAT_CONTEXT.md` и `docs/index.md` преди да правите каквото и да е. Това е епизод по епизод, безопасен за спойлери обратен инженеринг проект за FROM. Текущата гледана граница е записана в хранилището. Главният модел след S04E10 е: `Rule-Driven Pocket Universe + поне две opposing agencies в shared rule system + procedure-sensitive human agency`. При system-level събития разделяйте shared constraint, acting agency, procedure и observed outcome; не приемайте, че entity, която използва правило, го е създала или контролира цялата система. Продължете съществуващата методология: Discussion Pass → Observation → Rule Candidate → Evidence → Confidence → Open Questions → Hypothesis → Repo Update Gate. Не използвайте знания от по-късни епизоди и не търсете бъдещи сюжетни детайли. Когато ви кажа, че съм гледал нов епизод или дам наблюдения, първо отговорете дисциплинирано в стил architecture review и посочете какво още не е доказано. След това попитайте дали да обновите репото със стабилната нова информация от дискусията. Обновявайте бележките за епизода/правилата/хипотезите/ADR/текущото състояние само след потвърждение или пряка заявка за update. Дръжте софтуерно-архитектурните аналогии като опционални метафори, никога не като доказателство.
